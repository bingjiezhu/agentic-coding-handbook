# 小步实现，给出具体反馈

![小步实现，给出具体反馈](../../assets/diagrams/zh/p_build.svg)

## 围绕一段完整操作推进

1. **保留可恢复的版本。**Git 用来记录与比较版本。先保护已有改动，再用分支（独立的版本线）开展本轮工作。完成一段并检查通过后，提交一次本地版本，说明改了什么。提交是本地存档，推送是上传到远程仓库；工具的撤销记录不能替代版本保存。

1. **先接通一条真实路径。**让用户能从第一步操作走到真实结果，需保存的内容确实保存，再增加其他功能。界面工作可先看预览确认布局，再接真实数据；预览完成不等于功能完成。

1. **根据实际画面反馈。**提供截图或参考文件，说明“位置、当前表现、目标表现、保持不变的部分”。一次反馈聚焦一组相关问题，改后重新打开核对。

### 实现一轮可检查的改动

```text
项目与需求：[位置；无文档则写明要求]。本轮完成[功能范围]，按[关键检查点]推进；允许修改[范围]，保留[已有功能与样式]，参考[文件或截图；无则注明]。

核对已有改动，用版本记录或备份保留可恢复基线，不夹带他人改动。按[可运行的完成检查]在[预算]内实现、检查和修复；缺少关键材料先说明，遇未授权操作、关键取舍或重复失败无新线索时暂停相关工作。接通入口、处理、保存与反馈；标明模拟数据、未完成功能或固定答案。

说明关键改动与数据去向，列出对应文件；运行项目，给出可打开的位置、检查步骤和实际结果。界面改动实际点击、输入、刷新并对照截图；缺工具则给人工步骤，保留未验证状态。单独保存本轮改动；仅在获准时本地提交，不推送。更新已有任务与进度；按[位置、当前表现、目标表现、保持不变项]继续修改，不重写无关部分，改变目标前说明取舍。
```

## 每一轮都应积累成果

修改前保留的可用版本叫基线。满意一版就保存其版本、运行方法和检查结果，再开始下一轮；对比新旧时使用同一标准。小步推进便于定位收益与退步，避免一次重写丢掉已认可的功能。先亲自走完关键操作，再给具体反馈；没有变好，就恢复基线或缩小改动。
