# Twelve Chapters at a Glance

Clarify goals and trade-offs, preserve context in project files, and leave a verifiable result after each increment.

| Ch. | Topic | Core idea and action |
| --- | --- | --- |
| 01 | Define an actionable task | **Define outcomes and trade-offs.** Discuss and write the spec; people review scope and observable acceptance criteria. |
| 02 | Connect project files | **Keep context in files.** Index requirements, evidence and progress; reread after compaction or a new session. |
| 03 | Understand before changing | **Research before architecture.** Compare reuse, adaptation and a new build; verify sources, fit and key unknowns. |
| 04 | Use Spec Kit | **Keep requirements connected to execution.** Maintain specs, plans and tasks; checked boxes do not prove completion. |
| 05 | Build in small steps | **Make each round verifiable and recoverable.** Save a baseline, connect real behavior and give precise feedback. |
| 06 | Check actual use | **Derive expectations from requirements.** Verify full workflows and saved data; separate pass, fail and unverified. |
| 07 | Diagnose before editing | **Make failures reusable evidence.** Record hypotheses, conditions and results; keep regression checks after repairs. |
| 08 | Split independent work | **Parallelize independent tasks.** Specify inputs and scope; reconcile evidence and measure cost before scaling. |
| 09 | Review independently | **Verify review findings too.** Read requirements and the current version; report triggers and evidence; recheck fixes. |
| 10 | Resume long tasks | **Advance a queue of specs.** Define dependencies, acceptance and stop conditions; save results and verify before resuming. |
| 11 | Reuse rules and Skills | **Keep methods that repeatedly help.** Rules hold conventions, Skills hold methods and scripts run fixed steps; test actual reuse. |
| 12 | Pilot, then scale | **Validate the process first.** Pilot common and difficult cases, track every item, resume gaps and measure time and rework. |

**The thread through all twelve chapters:** People own goals, judgment and final acceptance. AI executes within an agreed scope. Files preserve requirements, decisions and experience; evidence shows what is complete. Organize the project before adding automation.

Choose methods for the situation; tool behavior depends on version and configuration.
